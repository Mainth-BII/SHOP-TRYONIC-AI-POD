## 1. DOCUMENT SUMMARY
The POD T-Shirt platform is an end-to-end e-commerce system that allows users (Guests and Logged-in Customers) to browse custom T-shirt templates, generate artwork using AI, customize designs on a 2D/3D editor canvas, and place physical orders. It includes backend flows for admins to manage users, orders, and AI quotas.

## 2. USE CASES IDENTIFIED
**UC01: Guest & User Authentication**
- **Actor:** Guest, Customer
- **Trigger:** Click Login/Signup
- **Main Flow:** Register via Email/Google/FB -> Login -> Access Profile
- **Alternative:** Guest accesses editor ("Try First, Login Later")
- **Exception:** Login fails (wrong credentials, locked account)
- **Business Rules:** Default session 24h, Remember me 30d

**UC02: AI Artwork Generation**
- **Actor:** Customer, Guest
- **Trigger:** Enter text prompt and click Generate
- **Main Flow:** Deduct 1 credit -> Show loading -> Return 4 preview images
- **Exception:** Out of Credits -> Show upgrade prompt
- **Business Rules:** Guest = 2 generations/day/IP. Free User = 10 generations/day. Auto reset every 24h.

**UC03: Workspace & Editor (Canvas)**
- **Actor:** Customer, Guest
- **Trigger:** Open a Template or Blank Canvas
- **Main Flow:** Upload Image / Generate AI Art -> Add Text -> Drag/Scale/Rotate -> View 3D Mockup -> Save Design
- **Alternative:** Smart Fit size suggestion based on Height/Weight/Gender
- **Exception:** Image < 150 DPI -> Show Low Quality warning
- **Business Rules:** Upload max 25MB (PNG/JPG). Guest must login when saving or adding to cart.

**UC04: Checkout & Payment**
- **Actor:** Customer
- **Trigger:** Add design to cart and click Checkout
- **Main Flow:** Input shipping -> Select Delivery -> Apply Discount (opt) -> Pay via VNPay -> Receive Email
- **Alternative:** Standard (5-7d) vs Express Delivery (2-3d)
- **Exception:** Payment timeout / Failed transaction -> Retry
- **Business Rules:** Order created as Pending, turns Paid upon successful payment.

**UC05: Admin Content & User Management**
- **Actor:** Admin
- **Trigger:** Login to CMS Dashboard
- **Main Flow:** View metrics -> Lock/Unlock users -> Export CSV -> Configure AI daily limit
- **Business Rules:** Soft delete users sends email notification.

## 3. ANALYSIS FINDINGS

### ✅ Strengths
- **Quotas Clearly Defined:** The AI Credit usage limits (2/day for Guest, 10/day for Free) and the reset rules (24h) are highly testable.
- **Visual Validation Constraints:** The spec accurately notes DPI requirements (< 150 DPI = Low Quality Warning) and File upload constraints (PNG/JPG, max 25MB).
- **Guest vs Customer Separation:** The "Try First, Login Later" boundary is explicitly tracked down to the physical order stage.

### ⚠️ Gaps — Must Fix Before Testing
- **Missing:** Exact constraints on "Smart Fit" inputs — needed for boundary validaton (min/max Height/Weight).
- **Missing:** Specific structure/length of the Discount Code (US-23) — needed to write boundary and negative TCs.
- **Visual Integrity Risk:** The Editor 3D Viewer does not explicitly state its fallback behavior on low-end mobile devices (WebGL crash risk).

### 🔴 Contradictions
- **Conflict:** US-39 describes 2-4 variations for AI Art, while AC F01 explicitly dictates exactly "4 variations". I will test assuming 4.

### 💡 Recommendations for BA
- **Suggest:** Add explicit HTTP Status Codes and timeout expectations for the VNPay integration workflow because network drop processing is critical for e-com orders.
- **Suggest:** Specify if the 2-guest-limit IP tracking resets completely at midnight UTC or rolling 24-hours for tighter boundary tests.
